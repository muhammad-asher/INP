1. Core Spring Boot Fundamentals

Auto-Configuration

Auto-configuration is Spring Boot's magic that automatically configures your application based on the dependencies you add to your project.

How It Works

  1. @EnableAutoConfiguration triggers the auto-configuration process
  2. Spring Boot scans META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports (or spring.factories in older versions)
  3. Each auto-configuration class has conditions (@ConditionalOnClass, @ConditionalOnMissingBean)
  4. Only configurations whose conditions are met are applied
🌍 Real-World Example

When you add spring-boot-starter-data-jpa and H2 database to your project, Spring Boot automatically:

  • Configures a DataSource pointing to H2
  • Creates an EntityManagerFactory
  • Enables transaction management
  • Sets up repository scanning

You write zero configuration code!

Spring Boot Starters

Starters are dependency descriptors that bundle related dependencies together. They follow the naming convention: spring-boot-starter-*.

Starter What It Includes Use Case
spring-boot-starter-web Tomcat, Spring MVC, Jackson, validation RESTful web applications
spring-boot-starter-data-jpa Hibernate, Spring Data JPA, HikariCP Database access with JPA
spring-boot-starter-security Spring Security, auth features Authentication & authorization
spring-boot-starter-test JUnit 5, Mockito, AssertJ, Spring Test Testing Spring applications
🌍 Real-World Example: Starting a New Project

Instead of manually adding 15 dependencies for a web API project (Jackson, validation, embedded server, logging, etc.), you add one line:

<!-- Just add this to pom.xml -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

Dependency Injection (DI) & IoC Container

Dependency Injection is a design pattern where objects receive their dependencies from external sources rather than creating them internally. Spring's IoC (Inversion of Control) container manages object creation and dependency injection.

Types of Injection

// ❌ Field Injection (NOT Recommended)
@Service
public class UserService {
    @Autowired
    private UserRepository userRepository;  // Hard to test, hides dependencies
}

// ❌ Setter Injection (Rarely Used)
@Service
public class UserService {
    private UserRepository userRepository;
    
    @Autowired
    public void setUserRepository(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}

// ✅ Constructor Injection (BEST PRACTICE)
@Service
public class UserService {
    private final UserRepository userRepository;  // immutable
    
    // @Autowired is optional for single constructor since Spring 4.3
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}
Why Constructor Injection is Best:
  • Dependencies are explicit and visible
  • Fields can be final (immutability)
  • Easy to test - just pass mock objects
  • Fails fast if dependency is missing

3. Building RESTful APIs

HTTP Mapping Annotations

@RestController
@RequestMapping("/api/v1/books")
public class BookController {
    
    private final BookService bookService;
    
    public BookController(BookService bookService) {
        this.bookService = bookService;
    }
    
    @GetMapping                          // GET /api/v1/books
    public List<Book> getAllBooks() {
        return bookService.findAll();
    }
    
    @GetMapping("/{id}")                 // GET /api/v1/books/123
    public Book getBook(@PathVariable Long id) {
        return bookService.findById(id);
    }
    
    @GetMapping("/search")               // GET /api/v1/books/search?title=Spring
    public List<Book> search(@RequestParam String title) {
        return bookService.searchByTitle(title);
    }
    
    @PostMapping                         // POST /api/v1/books
    public ResponseEntity<Book> createBook(@Valid @RequestBody BookDTO dto) {
        Book created = bookService.create(dto);
        return ResponseEntity
            .status(HttpStatus.CREATED)
            .body(created);
    }
    
    @PutMapping("/{id}")                 // PUT /api/v1/books/123
    public Book updateBook(@PathVariable Long id, @RequestBody BookDTO dto) {
        return bookService.update(id, dto);
    }
    
    @DeleteMapping("/{id}")              // DELETE /api/v1/books/123
    public ResponseEntity<Void> deleteBook(@PathVariable Long id) {
        bookService.delete(id);
        return ResponseEntity.noContent().build();
    }
    
    @PatchMapping("/{id}")               // PATCH /api/v1/books/123 (partial update)
    public Book patchBook(@PathVariable Long id, @RequestBody Map<String, Object> updates) {
        return bookService.partialUpdate(id, updates);
    }
}

Global Exception Handling

Centralize error handling across all controllers using @ControllerAdvice.

@RestControllerAdvice  // Global exception handler for REST APIs
public class GlobalExceptionHandler {
    
    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ErrorResponse handleNotFound(ResourceNotFoundException ex) {
        return new ErrorResponse(
            HttpStatus.NOT_FOUND.value(),
            ex.getMessage(),
            LocalDateTime.now()
        );
    }
    
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleValidationErrors(MethodArgumentNotValidException ex) {
        List<String> errors = ex.getBindingResult()
            .getFieldErrors()
            .stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.toList());
        
        return new ErrorResponse(400, "Validation failed", errors);
    }
    
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ErrorResponse handleGenericException(Exception ex) {
        // Log the real error
        log.error("Unexpected error", ex);
        // Return safe message to client
        return new ErrorResponse(500, "An unexpected error occurred", null);
    }
}

// Custom exception
public class ResourceNotFoundException extends RuntimeException {
    public ResourceNotFoundException(String resource, Long id) {
        super(resource + " not found with id: " + id);
    }
}
🌍 Real-World Example

Without global exception handling, a NullPointerException might leak stack traces to users. With @ControllerAdvice, all exceptions are caught, logged properly, and converted to user-friendly JSON error responses.

Entity Relationships (CRITICAL!)

Fetch Types Matter! Improper fetch type selection is the #1 cause of N+1 query problems and performance issues. 
@Entity
public class Author {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    private String name;
    
    // One author has many books
    @OneToMany(mappedBy = "author", fetch = FetchType.LAZY)  // LAZY is default
    private List<Book> books;
}

@Entity
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    private String title;
    
    // Many books belong to one author
    @ManyToOne(fetch = FetchType.LAZY)  // Override EAGER default!
    @JoinColumn(name = "author_id")
    private Author author;
    
    // Many-to-many: Book has many categories
    @ManyToMany
    @JoinTable(
        name = "book_categories",
        joinColumns = @JoinColumn(name = "book_id"),
        inverseJoinColumns = @JoinColumn(name = "category_id")
    )
    private Set<Category> categories;
}

Lazy vs Eager Fetching

LAZY EAGER
Loaded only when accessed Loaded immediately with parent
Default for @OneToMany, @ManyToMany Default for @ManyToOne, @OneToOne
Better performance usually Can cause N+1 if not careful
Requires open session to access Always available
Best Practice: Always use LAZY fetching. When you need related data, use JOIN FETCH or EntityGraph to load it efficiently in a single query. 
// Avoiding N+1 with JOIN FETCH
@Query("SELECT a FROM Author a JOIN FETCH a.books WHERE a.id = :id")
Optional<Author> findByIdWithBooks(@Param("id") Long id);

// Or use EntityGraph
@EntityGraph(attributePaths = {"books"})
Optional<Author> findById(Long id);

@Transactional

Manages database transactions declaratively. Without it, each repository call is a separate transaction.

@Service
public class OrderService {
    
    @Transactional  // Everything in this method is one transaction
    public Order createOrder(OrderDTO dto) {
        Order order = new Order();
        orderRepository.save(order);
        
        for (ItemDTO item : dto.getItems()) {
            OrderItem orderItem = new OrderItem(order, item);
            orderItemRepository.save(orderItem);
            
            // Reduce inventory
            inventoryService.reduceStock(item.getProductId(), item.getQuantity());
        }
        
        // If ANY of the above fails, ALL changes are rolled back
        return order;
    }
    
    @Transactional(readOnly = true)  // Optimization hint for read-only operations
    public List<Order> findAllOrders() {
        return orderRepository.findAll();
    }
}

Propagation Levels

Propagation Behavior
REQUIRED (default) Join existing transaction or create new
REQUIRES_NEW Always create new transaction (suspend existing)
MANDATORY Must run in existing transaction (throw if none)
NOT_SUPPORTED Run without transaction (suspend if exists)
🌍 Real-World Example: Audit Logging

You want to log every action, even if the main transaction fails:

@Service
public class PaymentService {
    
    @Transactional
    public void processPayment(Payment payment) {
        // This might fail
        paymentGateway.charge(payment);
        
        // Log should persist even if above fails
        auditService.log(payment);  // Uses REQUIRES_NEW
    }
}

@Service
public class AuditService {
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void log(Object event) {
        // Runs in separate transaction - always committed
        auditRepository.save(new AuditLog(event));
    }
}

5. Spring Security

Security Filter Chain

Spring Security uses a filter chain to process security for each request. Filters execute in order, and each has a specific responsibility.

@Configuration
@EnableWebSecurity
public class SecurityConfig {
    
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // Disable CSRF for stateless APIs (using JWT)
            .csrf(csrf -> csrf.disable())
            
            // Configure authorization rules
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/user/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().authenticated()
            )
            
            // Stateless session for JWT
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            
            // Add JWT filter before username/password filter
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        
        return http.build();
    }
    
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

Authentication with UserDetailsService

@Service
public class CustomUserDetailsService implements UserDetailsService {
    
    private final UserRepository userRepository;
    
    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByEmail(username)
            .orElseThrow(() -> new UsernameNotFoundException("User not found: " + username));
        
        return org.springframework.security.core.userdetails.User.builder()
            .username(user.getEmail())
            .password(user.getPassword())  // BCrypt encoded
            .roles(user.getRoles().toArray(new String[0]))
            .build();
    }
}

JWT Implementation Overview

@Component
public class JwtTokenProvider {
    
    @Value("${jwt.secret}")
    private String secretKey;
    
    @Value("${jwt.expiration}")
    private long validityInMs;
    
    public String createToken(String username, List<String> roles) {
        Claims claims = Jwts.claims().setSubject(username);
        claims.put("roles", roles);
        
        Date now = new Date();
        Date validity = new Date(now.getTime() + validityInMs);
        
        return Jwts.builder()
            .setClaims(claims)
            .setIssuedAt(now)
            .setExpiration(validity)
            .signWith(SignatureAlgorithm.HS256, secretKey)
            .compact();
    }
    
    public boolean validateToken(String token) {
        try {
            Jwts.parser().setSigningKey(secretKey).parseClaimsJws(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
    
    public String getUsername(String token) {
        return Jwts.parser().setSigningKey(secretKey)
            .parseClaimsJws(token).getBody().getSubject();
    }
}
🌍 Real-World JWT Flow
  1. User logs in with username/password
  2. Server validates credentials, returns JWT
  3. Client stores JWT (localStorage or httpOnly cookie)
  4. Client sends JWT in Authorization header: Bearer {token}
  5. JwtFilter validates token and sets SecurityContext

@WebMvcTest(UserController.class)  // Only load UserController
class UserControllerTest {

    private MockMvc mockMvc;
    
    @MockBean  // Mock the service dependency

        User user = new User(1L, "John", "john@email.com");

            .andExpect(status().isOk())
            .andExpect(jsonPath("$.name").value("John"))
            .andExpect(jsonPath("$.email").value("john@email.com"));
    }
    
    @Test
    void shouldReturn404WhenNotFound() throws Exception {
        when(userService.findById(999L)).thenReturn(Optional.empty());
        
        mockMvc.perform(get("/api/users/999"))
            .andExpect(status().isNotFound());
    }
    
    @Test
    void shouldCreateUser() throws Exception {
        User user = new User(1L, "Jane", "jane@email.com");
        when(userService.create(any(UserDTO.class))).thenReturn(user);

                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"name\":\"Jane\",\"email\":\"jane@email.com\"}"))
            .andExpect(status().isCreated())
            .andExpect(jsonPath("$.id").value(1));

7. Microservices & Cloud Patterns

Service Discovery (Eureka)

Services register themselves with a discovery server. Other services look up addresses dynamically instead of hardcoding URLs.

🌍 Real-World Example

OrderService needs to call InventoryService. Instead of hardcoding http://inventory:8080, it asks Eureka "Where is InventoryService?" and gets the current address (which might change due to scaling or restarts).

Circuit Breaker (Resilience4j)

Prevents cascading failures by failing fast when a service is down.

@Service
public class PaymentService {
    
    @CircuitBreaker(name = "paymentService", fallbackMethod = "paymentFallback")
    @Retry(name = "paymentService")
    public PaymentResult processPayment(Payment payment) {
        // Call external payment gateway
        return paymentGateway.charge(payment);
    }
    
    private PaymentResult paymentFallback(Payment payment, Exception ex) {
        // Return graceful fallback
        return PaymentResult.pending("Service temporarily unavailable. Retrying later.");
    }
}

# application.yml
resilience4j:
  circuitbreaker:
    instances:
      paymentService:
        slidingWindowSize: 10
        failureRateThreshold: 50
        waitDurationInOpenState: 10000

                return Health.up()
                    .withDetail("database", "PostgreSQL")
                    .withDetail("status", "connected")
                    .build();
            }
        } catch (SQLException e) {
            return Health.down()
                .withException(e)
                .build();
        }
        return Health.unknown().build();
    }
}

Logging with SLF4J & MDC

Use MDC (Mapped Diagnostic Context) to add contextual information to all logs in a request.

@Component
public class RequestLoggingFilter extends OncePerRequestFilter {
    
    @Override
    protected void doFilterInternal(HttpServletRequest request, 
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String requestId = UUID.randomUUID().toString();
        
        // Add to MDC - appears in all logs for this request
        MDC.put("requestId", requestId);
        MDC.put("userId", getCurrentUserId());
        
        try {
            chain.doFilter(request, response);
        } finally {
            MDC.clear();  // Important: clean up
        }
    }
}

// logback-spring.xml pattern
// %X{requestId} %X{userId} %msg%n
// Output: abc-123 user456 Processing order...

// In your code - requestId automatically included
@Service
public class OrderService {
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);
    
    public void processOrder(Order order) {
        log.info("Processing order {}", order.getId());
        // Log output: abc-123 user456 Processing order 789
    }
}

    public void reportCurrentTime() {

    }

    public void dailyCleanup() {

    }

}

Async Methods

@Configuration
@EnableAsync
public class AsyncConfig {
    
    @Bean
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(2);
        executor.setMaxPoolSize(10);
        executor.setQueueCapacity(500);
        executor.setThreadNamePrefix("async-");
        executor.initialize();
        return executor;
    }
}

@Service
public class EmailService {
    
    @Async  // Runs in separate thread
    public void sendWelcomeEmail(User user) {
        // This doesn't block the caller
        emailClient.send(user.getEmail(), "Welcome!");
    }
    
    @Async
    public CompletableFuture<EmailResult> sendEmailWithResult(Email email) {
        EmailResult result = emailClient.send(email);
        return CompletableFuture.completedFuture(result);
    }
}

// Usage
@Service
public class UserService {
    
    public User registerUser(UserDTO dto) {
        User user = userRepository.save(convertToEntity(dto));
        
        emailService.sendWelcomeEmail(user);  // Doesn't wait!
        
        return user;  // Returns immediately
    }
}
🌍 Real-World Example

User registers → Save user immediately → Return response → Send welcome email asynchronously in background. User doesn't wait 3-5 seconds for email to be sent.

10. Profiles & Deployment

Profiles

Profiles allow different configurations for different environments (dev, test, prod).

# application.yml (default)
spring:
  profiles:
    active: dev  # Default profile

---
# application-dev.yml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
  jpa:
    show-sql: true

logging:
  level:
    root: DEBUG

---
# application-prod.yml
spring:
  datasource:
    url: jdbc:postgresql://prod-db:5432/myapp
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    show-sql: false

logging:
  level:
    root: WARN
# Activate profile
java -jar app.jar --spring.profiles.active=prod

# Or via environment variable
SPRING_PROFILES_ACTIVE=prod java -jar app.jar

Profile-Specific Beans

@Configuration
public class StorageConfig {

    @Profile("dev")

        return new LocalStorageService("/tmp/uploads");
    }
    
    @Bean
    @Profile("prod")

        return new S3StorageService();
    }
}

FROM eclipse-temurin:17-jre-alpine

# Multi-stage build (smaller image)

FROM eclipse-temurin:17-jre-alpine

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

docker build -t myapp:v1 .
docker run -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=prod \
  -e DB_PASSWORD=secret \
  myapp:v1

JAR vs WAR Packaging

JAR (Recommended) WAR
Embedded server (Tomcat) External server required
java -jar app.jar Deploy to Tomcat/JBoss
Cloud-native, Docker-friendly Traditional deployment
Self-contained Shared server resources
🍃 Spring Boot Recommendation

Always use JAR packaging with embedded server unless you have a specific requirement to deploy to an existing application server. JAR packaging is the modern, cloud-native approach.
