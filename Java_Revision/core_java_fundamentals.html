Core Java Fundamentals

Explained simply with real-world analogies.

OOP Principles

The Foundation

Encapsulation: Binding data and methods together and hiding the internal details (using private fields and public getters/setters).

Inheritance: One class acquiring the properties and behaviors of another class to promote code reuse.

Polymorphism: The ability of an object to take on many forms. Same method name, different behavior.

Abstraction: Hiding implementation details and showing only functionality to the user.

Real World Analogy: Encapsulation

Think of a Medical Capsule. The medicine (data) is enclosed inside the capsule shell (class) to protect it from outside contamination. You utilize it, but don't touch the chemicals directly.

Real World Analogy: Polymorphism

Think of a "Sound" button. If you press it for a Dog object, it "Barks". If you press it for a Cat object, it "Meows". The action (press button) is the same, but the result depends on the object type.

Class vs Object

Building Blocks

Class: A blueprint or template from which objects are created. It defines properties and behaviors but consumes no memory until instantiated.

Object: A real-world entity created from the class blueprint. It has state (variables) and behavior (methods).

Real World Analogy

Class: An Architect's Blueprint for a house. You can't live in the blueprint.

Object: The actual House built from that blueprint. You can live in it, open doors, etc. You can build 50 houses (objects) from one blueprint (class).

Interface vs Abstract Class

Structure

Interface: A strict contract. It defines what needs to be done, but not how. A class can implement multiple interfaces.

Abstract Class: A partial implementation. It can provide some common functionality while leaving other parts for subclasses to define.

Real World Analogy: Interface

A Power Socket. The wall socket (Interface) defines the shape (contract). A TV, Laptop, or Lamp (Implementing Classes) must fit that shape to work, but they all do different things internally.

Real World Analogy: Abstract Class

A generic "Bird". We know all birds have beaks and lay eggs (concrete methods in Abstract Class). But how they "move" differs (Penguin swims, Eagle flies). The Abstract Class defines common traits but leaves "movement" abstract.

Access Modifiers

Security
  • private: Visible only within the same class.
  • default (no keyword): Visible within the same package.
  • protected: Visible within package and subclasses (even outside package).
  • public: Visible everywhere.
Real World Analogy
  • Private: Your personal diary. Only you can read it.
  • Default: Office rumors. Known only to people in the same department (package).
  • Protected: Family wealth. Accessible to family members (subclasses) even if they live elsewhere.
  • Public: A Billboard on the highway. Anyone can see it.

Exception Handling

Safety

Try-Catch: Attempt a risky operation (try), and if it fails, handle the problem gracefully (catch) instead of crashing.

Checked vs Unchecked: Checked are verified at compile-time (Java forces you to handle them). Unchecked happen at runtime (logic errors).

Real World Analogy

Try-Catch: Imagine a trapezist (acrobat). The acrobat performing is the try block. The safety net below is the catch block. If they fall (exception), the net catches them so they don't die (crash). The show can continue.

Checked Exception: Airport Security. They check your bag before you fly (compile time). You MUST deal with the water bottle before proceeding.

String Immutability

Data Integrity

In Java, once a String object is created, its value cannot be changed. If you modify it, a new object is created.

Real World Analogy

Think of a Stone Carving. If you carve "Hello" into a stone, you can't change it to "Help" by rubbing it out. You must take a fresh stone and carve the new word. The original stone remains "Hello" forever.

(In contrast, StringBuilder is like a Whiteboard where you can erase and rewrite).
