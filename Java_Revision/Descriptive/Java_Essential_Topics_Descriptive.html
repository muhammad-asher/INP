1. Core Java Fundamentals

Object-Oriented Programming (OOP) Principles

OOP is a programming paradigm that organizes software design around data (objects) rather than functions and logic. Java is fundamentally an OOP language.

Encapsulation

Definition: Encapsulation is the bundling of data (variables) and methods that operate on that data within a single unit (class), while restricting direct access to some components.

🌍 Real-World Example: Bank Account

Think of a bank ATM machine. You can deposit, withdraw, and check balance, but you cannot directly access the bank's internal systems or modify your balance without going through proper channels.

public class BankAccount {
    private double balance;  // Hidden from outside
    
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
    
    public double getBalance() {
        return balance;  // Controlled access
    }
}

Inheritance

Definition: Inheritance allows a class to inherit properties and methods from another class, promoting code reuse and establishing a parent-child relationship.

🌍 Real-World Example: Vehicle Hierarchy

All cars, bikes, and trucks are vehicles. They share common properties like speed, color, and methods like start() and stop(). A Car "is-a" Vehicle.

class Vehicle {
    protected String brand;
    public void start() { System.out.println("Vehicle started"); }
}

class Car extends Vehicle {
    private int numberOfDoors;
    
    @Override
    public void start() {
        System.out.println("Car engine started with key");
    }
}

Polymorphism

Definition: Polymorphism means "many forms." It allows objects of different classes to be treated as objects of a common superclass. There are two types: compile-time (method overloading) and runtime (method overriding).

🌍 Real-World Example: Payment System

When you "pay" at a store, you might use cash, credit card, or mobile payment. The action is "pay," but the implementation differs based on the payment method.

interface Payment {
    void pay(double amount);
}

class CreditCard implements Payment {
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " using Credit Card");
    }
}

class CashPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid $" + amount + " in cash");
    }
}

// Usage - same interface, different behavior
Payment payment = new CreditCard();
payment.pay(100);  // Outputs: Paid $100 using Credit Card

Abstraction

Definition: Abstraction hides complex implementation details and shows only the essential features of an object to the outside world.

🌍 Real-World Example: TV Remote

When you press the "Volume Up" button on a TV remote, you don't need to know the internal circuit operations. You just use the abstract interface (buttons) to control the TV.

Classes, Objects, and Constructors

Class: A blueprint or template for creating objects. It defines properties (fields) and behaviors (methods).

Object: An instance of a class - a concrete entity created from the class blueprint.

Types of Constructors

  • Default Constructor: No-argument constructor (provided by Java if you don't define any)
  • Parameterized Constructor: Takes arguments to initialize object state
  • Copy Constructor: Creates a new object by copying another object (Java doesn't provide this automatically)
🌍 Real-World Example: Employee Registration System

When HR creates a new employee record, they might create a blank form (default), fill in details (parameterized), or copy an existing employee's role to a new hire (copy).

public class Employee {
    private String name;
    private int id;
    
    // Default Constructor
    public Employee() {
        this.name = "Unknown";
        this.id = 0;
    }
    
    // Parameterized Constructor
    public Employee(String name, int id) {
        this.name = name;
        this.id = id;
    }
    
    // Copy Constructor
    public Employee(Employee other) {
        this.name = other.name;
        this.id = other.id;
    }
}

Interface vs Abstract Class

Feature Interface Abstract Class
Methods Abstract by default (can have default/static since Java 8) Can have both abstract and concrete methods
Variables public static final only Can have any type of variables
Multiple Inheritance Yes (a class can implement multiple interfaces) No (a class can extend only one abstract class)
When to Use Define a contract/capability Share common code among related classes
🌍 Real-World Example

Interface (Flyable): Birds can fly, airplanes can fly, drones can fly. They're not related, but they share the "flyable" capability.

Abstract Class (Animal): Dogs, cats, and lions are all animals. They share common properties like age and weight, and methods like eat() and sleep().

Access Modifiers

Access modifiers control the visibility and accessibility of classes, methods, and variables.

Modifier Same Class Same Package Subclass Different Package
public ✅ ✅ ✅ ✅
protected ✅ ✅ ✅ ❌
default (no modifier) ✅ ✅ ❌ ❌
private ✅ ❌ ❌ ❌
🌍 Real-World Example: Company Access Levels

public: Company website - anyone can access
protected: Internal training documents - employees and subsidiaries
default: Department meetings - only people in that department
private: CEO's personal notes - only the CEO

Keywords: final, static, this, super

final Keyword

  • final variable: Cannot be reassigned (constant)
  • final method: Cannot be overridden by subclasses
  • final class: Cannot be extended

static Keyword

Belongs to the class rather than an instance. Shared among all objects.

🌍 Real-World Example: Counter

A static counter in a "Visitor" class tracks total visitors across all instances, like a turnstile counter at a museum entrance.

class Visitor {
    private static int totalVisitors = 0;  // Shared
    private String name;
    
    public Visitor(String name) {
        this.name = name;
        totalVisitors++;
    }
    
    public static int getTotalVisitors() {
        return totalVisitors;
    }
}

this Keyword

Refers to the current object instance. Used to distinguish between instance variables and parameters.

super Keyword

Refers to the parent class. Used to call parent constructors or methods.

Exception Handling

Exception handling is a mechanism to handle runtime errors gracefully without crashing the program.

Checked vs Unchecked Exceptions

  • Checked Exceptions: Must be handled at compile time (IOException, SQLException)
  • Unchecked Exceptions: Runtime exceptions (NullPointerException, ArrayIndexOutOfBoundsException)
🌍 Real-World Example: File Processing

When reading a file, the file might not exist (checked exception - you must plan for it). But if you try to access a null object, that's a programming error (unchecked).

// try-with-resources (automatically closes resources)
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {
    String line = reader.readLine();
} catch (FileNotFoundException e) {
    System.out.println("File not found: " + e.getMessage());
} catch (IOException e) {
    System.out.println("Error reading file: " + e.getMessage());
} finally {
    System.out.println("Cleanup completed");
}

// Custom Exception
public class InsufficientFundsException extends Exception {
    public InsufficientFundsException(String message) {
        super(message);
    }
}
throw vs throws: throw is used to explicitly throw an exception. throws is used in method signature to declare that a method might throw an exception.

2. Collections Framework & Generics

List Interface

Lists are ordered collections that allow duplicate elements and maintain insertion order.

ArrayList

Backed by a dynamic array. Fast random access (O(1)), slow insertions/deletions in middle (O(n)).

LinkedList

Doubly-linked list. Fast insertions/deletions (O(1) at ends), slow random access (O(n)).

🌍 Real-World Example

ArrayList: Like a bookshelf where you can quickly grab any book by position, but inserting a book in the middle requires shifting others.

LinkedList: Like a train where adding/removing carriages at ends is easy, but getting to carriage #50 requires walking through all previous ones.

Operation ArrayList LinkedList
get(index) O(1) O(n)
add(element) at end O(1) amortized O(1)
add(index, element) O(n) O(n)
remove(index) O(n) O(n)

Set Interface

Sets are collections that do not allow duplicate elements.

HashSet

Backed by a HashMap. No order guarantee. O(1) for add, remove, contains.

LinkedHashSet

Maintains insertion order using a linked list.

TreeSet

Sorted order (natural or custom). O(log n) operations. Backed by Red-Black Tree.

🌍 Real-World Example: Email List

Use HashSet to store email subscribers - no duplicates, fast lookup to check if someone is already subscribed.

Map Interface

Maps store key-value pairs. Keys must be unique.

HashMap Internal Working

  1. Computes hashCode() of the key
  2. Maps hash to bucket index using: index = hash & (n-1)
  3. If collision occurs, stores in linked list (Java 8+: converts to tree if bucket size > 8)
  4. On get(), uses equals() to find exact match in bucket
🌍 Real-World Example: Phone Directory

HashMap is like a phone directory where names (keys) map to phone numbers (values). You can quickly look up anyone's number by their name.

ConcurrentHashMap: Thread-safe version that allows concurrent reads and limited concurrent writes using segment locking (or CAS operations in Java 8+).

Comparable vs Comparator

Comparable Comparator
Defines natural ordering Defines custom ordering
compareTo(Object o) compare(Object o1, Object o2)
In the same class In a separate class
Single sorting sequence Multiple sorting sequences 
// Comparable - natural ordering by age
class Employee implements Comparable<Employee> {
    String name;
    int age;
    
    @Override
    public int compareTo(Employee other) {
        return this.age - other.age;
    }
}

// Comparator - custom ordering by name
Comparator<Employee> byName = (e1, e2) -> e1.name.compareTo(e2.name);
Collections.sort(employees, byName);

Generics

Generics provide type safety at compile time, eliminating the need for casting and preventing ClassCastException at runtime.

Wildcards

  • ? (Unbounded): Unknown type - List<?>
  • ? extends T (Upper Bounded): T or its subtypes - List<? extends Number>
  • ? super T (Lower Bounded): T or its supertypes - List<? super Integer>
🌍 Real-World Example: Garage

List<? extends Vehicle>: A garage that can hold any type of vehicle (Car, Bike, Truck) - you can take vehicles out but can't put specific types in.

List<? super Car>: A parking lot for Cars and any supertype - you can park Cars, but what you get out might be just "a Vehicle".

Type Erasure: Generics are implemented using type erasure - generic type information is removed at runtime and replaced with Object (or the bound). This is why you can't do new T() or instanceof T.

3. Java 8+ Features (Functional Programming)

Lambda Expressions

Lambda expressions are anonymous functions that provide a concise way to implement functional interfaces.

// Before Lambda
Runnable runnable = new Runnable() {
    @Override
    public void run() {
        System.out.println("Hello");
    }
};

// With Lambda
Runnable runnable = () -> System.out.println("Hello");

// Lambda with parameters
BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b;
🌍 Real-World Example: Event Handling

When you click a button in a GUI application, instead of creating a whole class to handle the click, you can use a lambda: button.onClick(() -> saveDocument())

Functional Interfaces

An interface with exactly one abstract method. Can be annotated with @FunctionalInterface.

Interface Method Use Case
Predicate<T> boolean test(T t) Filtering, validation
Function<T, R> R apply(T t) Transformation
Consumer<T> void accept(T t) Processing without return
Supplier<T> T get() Lazy generation of values 
Predicate<String> isLongName = name -> name.length() > 5;
Function<String, Integer> getLength = String::length;
Consumer<String> printer = System.out::println;
Supplier<LocalDate> today = LocalDate::now;

Stream API

Streams provide a declarative way to process collections of data using functional-style operations.

Intermediate vs Terminal Operations

  • Intermediate: Return a stream (lazy evaluation) - filter, map, flatMap, sorted, distinct
  • Terminal: Produce a result (triggers processing) - collect, forEach, reduce, count, findFirst
🌍 Real-World Example: Processing Orders

Filter orders by status, transform to order amounts, and calculate total revenue - all in a fluent pipeline.

List<Order> orders = getOrders();

// Process orders
double totalRevenue = orders.stream()
    .filter(order -> order.getStatus() == Status.COMPLETED)  // Filter
    .map(Order::getAmount)                                    // Transform
    .reduce(0.0, Double::sum);                               // Aggregate

// Collect to list
List<String> customerNames = orders.stream()
    .map(Order::getCustomerName)
    .distinct()
    .sorted()
    .collect(Collectors.toList());

// FlatMap - Flatten nested structures
List<String> allItems = orders.stream()
    .flatMap(order -> order.getItems().stream())
    .collect(Collectors.toList());

Optional Class

Optional is a container that may or may not contain a non-null value. It helps avoid NullPointerException.

Optional<User> userOpt = findUserById(id);

// Safe operations
String name = userOpt
    .map(User::getName)
    .orElse("Anonymous");

// Throw exception if not present
User user = userOpt.orElseThrow(() -> new UserNotFoundException(id));

// Do something only if present
userOpt.ifPresent(u -> sendWelcomeEmail(u));
🌍 Real-World Example: Database Query

When querying a database for a user by ID, the user might not exist. Instead of returning null and risking NPE, return Optional<User> to make the absence explicit.

4. Multithreading & Concurrency

Thread Lifecycle

A thread goes through several states during its lifetime:

  • NEW: Thread created but not started
  • RUNNABLE: Thread is running or ready to run
  • BLOCKED: Waiting to acquire a lock
  • WAITING: Waiting indefinitely for another thread
  • TIMED_WAITING: Waiting for a specified time
  • TERMINATED: Thread has completed execution

Creating Threads

// Method 1: Extend Thread
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread running");
    }
}

// Method 2: Implement Runnable (Preferred - allows extending other classes)
class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Runnable running");
    }
}

// Method 3: Callable (Returns a result)
Callable<Integer> callable = () -> {
    return computeValue();
};
Future<Integer> future = executor.submit(callable);
Integer result = future.get();  // Blocks until result is ready

Synchronization

Synchronization prevents multiple threads from accessing shared resources simultaneously, avoiding race conditions.

🌍 Real-World Example: Bank Withdrawal

Two ATMs trying to withdraw from the same account simultaneously. Without synchronization, both might see $100 and both withdraw $100, resulting in -$100 balance.

public class BankAccount {
    private double balance;
    
    // Synchronized method
    public synchronized void withdraw(double amount) {
        if (balance >= amount) {
            balance -= amount;
        }
    }
    
    // Synchronized block (more granular)
    public void deposit(double amount) {
        synchronized(this) {
            balance += amount;
        }
    }
}

Volatile Keyword

Ensures visibility of changes across threads. When a variable is marked volatile, reads and writes go directly to main memory, not CPU cache.

Atomic Classes

Classes like AtomicInteger, AtomicLong provide thread-safe operations without explicit synchronization using Compare-And-Swap (CAS) operations.

Executor Framework

The Executor framework provides a high-level API for managing thread pools and task execution.

Pool Type Description Use Case
FixedThreadPool Fixed number of threads Known, bounded workload
CachedThreadPool Creates threads as needed, reuses idle ones Many short-lived tasks
ScheduledThreadPool For scheduled tasks Periodic/delayed execution
SingleThreadExecutor Single worker thread Sequential task execution 
ExecutorService executor = Executors.newFixedThreadPool(4);

// Submit tasks
Future<String> future = executor.submit(() -> {
    return "Result";
});

// CompletableFuture for async operations
CompletableFuture.supplyAsync(() -> fetchData())
    .thenApply(data -> processData(data))
    .thenAccept(result -> saveResult(result))
    .exceptionally(ex -> handleError(ex));

// Always shutdown
executor.shutdown();

5. Memory Management & JVM Internals

JVM Architecture

  • Class Loader: Loads .class files into memory (Bootstrap, Extension, Application loaders)
  • Runtime Data Areas: Method Area, Heap, Stack, PC Register, Native Method Stack
  • Execution Engine: Interpreter, JIT Compiler, Garbage Collector

Heap vs Stack

Heap Stack
Stores objects Stores local variables, method calls
Shared among threads Thread-specific
Garbage collected Automatically deallocated when method returns
Slower access Faster access

Garbage Collection

GC automatically reclaims memory occupied by objects that are no longer reachable.

Heap Generations

  • Young Generation (Eden + Survivor): New objects are created here. Minor GC occurs frequently.
  • Old/Tenured Generation: Long-lived objects. Major GC (Full GC) is less frequent but slower.
🌍 Real-World Example

Think of Young Gen as a nursery where new plants are placed. Those that survive are moved to the main garden (Old Gen). The gardener (GC) regularly cleans up dead plants from the nursery (Minor GC) and occasionally does a full cleanup of the entire garden (Full GC).

GC Algorithms

  • Serial GC: Single-threaded, stop-the-world
  • Parallel GC: Multi-threaded, good for throughput
  • G1 GC: Divides heap into regions, good balance of throughput and latency
  • ZGC: Very low pause times (sub-millisecond)

Reference Types

  • Strong Reference: Normal reference. Object won't be GC'd as long as strong reference exists.
  • Weak Reference: GC'd at next collection if no strong references. Used in WeakHashMap.
  • Soft Reference: GC'd only when memory is low. Good for caches.
  • Phantom Reference: Used to schedule post-mortem cleanup actions.

6. Input/Output (I/O) & Networking

Serialization

Serialization converts an object into a byte stream for storage or transmission. Deserialization reconstructs the object.

public class Employee implements Serializable {
    private static final long serialVersionUID = 1L;  // Version control
    private String name;
    private transient String password;  // Won't be serialized
}

// Serialize
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("emp.ser"))) {
    oos.writeObject(employee);
}

// Deserialize
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("emp.ser"))) {
    Employee emp = (Employee) ois.readObject();
}
serialVersionUID: A version number for the class. If you change the class structure, change this ID to prevent deserialization issues.

NIO (New I/O)

NIO provides non-blocking I/O operations using Channels and Buffers.

  • Channel: Bidirectional data highway (FileChannel, SocketChannel)
  • Buffer: Container for data (ByteBuffer, CharBuffer)
  • Selector: Monitors multiple channels for events (multiplexing)
🌍 Real-World Example: Server handling many connections

Like a receptionist who can watch multiple phone lines and handle whichever one rings, instead of having one person per phone line.

7. Design Patterns

Creational Patterns

Singleton Pattern

Ensures only one instance of a class exists throughout the application.

// Thread-safe Singleton with Double-Checked Locking
public class DatabaseConnection {
    private static volatile DatabaseConnection instance;
    
    private DatabaseConnection() {}
    
    public static DatabaseConnection getInstance() {
        if (instance == null) {
            synchronized (DatabaseConnection.class) {
                if (instance == null) {
                    instance = new DatabaseConnection();
                }
            }
        }
        return instance;
    }
}
🌍 Real-World Example: Database Connection Pool

Your application should have only one connection pool manager that all components use.

Factory Pattern

Creates objects without exposing creation logic. Client uses a common interface.

🌍 Real-World Example: Document Creator

A document factory that creates PDF, Word, or Excel documents based on the type requested.

Builder Pattern

Constructs complex objects step by step. Useful when an object has many optional parameters.

User user = User.builder()
    .name("John")
    .email("john@example.com")
    .age(30)
    .address("123 Main St")
    .build();

Structural Patterns

Adapter Pattern

Converts one interface to another that clients expect. Acts as a bridge between incompatible interfaces.

🌍 Real-World Example: Power Adapter

A travel power adapter lets you use your US laptop charger in European outlets.

Decorator Pattern

Adds behavior to objects dynamically without modifying their code.

🌍 Real-World Example: Coffee Shop

Start with basic coffee, then add milk decorator, sugar decorator, whipped cream decorator - each adds cost and features.

Behavioral Patterns

Observer Pattern

Defines a subscription mechanism to notify multiple objects about events.

🌍 Real-World Example: Newsletter Subscription

Subscribers get notified when a new blog post is published. They don't need to keep checking - they're automatically notified.

Strategy Pattern

Defines a family of algorithms and makes them interchangeable at runtime.

🌍 Real-World Example: Payment Processing

At checkout, customer chooses payment strategy: credit card, PayPal, or bank transfer. The checkout process remains the same, only the payment strategy changes.

8. Modern Java Features (Java 9 - 21)

Records (Java 16+)

Concise way to create immutable data carriers. Automatically generates constructor, getters, equals(), hashCode(), toString().

// Traditional way - lots of boilerplate
public class Point {
    private final int x;
    private final int y;
    public Point(int x, int y) { this.x = x; this.y = y; }
    public int getX() { return x; }
    // ... equals, hashCode, toString
}

// With Records - one line!
public record Point(int x, int y) {}

Sealed Classes (Java 17)

Restricts which classes can extend or implement a class/interface.

public sealed class Shape permits Circle, Rectangle, Triangle {}

public final class Circle extends Shape {}
public final class Rectangle extends Shape {}
public non-sealed class Triangle extends Shape {}  // Can be extended further

Virtual Threads (Java 21)

Lightweight threads managed by JVM, not OS. Can create millions of virtual threads for high-throughput concurrent applications.

// Create virtual threads easily
Thread.startVirtualThread(() -> {
    // Handle request
});

// Or with executor
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> handleRequest());
}
🌍 Real-World Example: Web Server

Handle 1 million concurrent HTTP requests without running out of threads. Each request gets its own virtual thread.

9. Testing & Quality

JUnit 5

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
    
    private Calculator calculator;
    
    @BeforeEach
    void setUp() {
        calculator = new Calculator();
    }
    
    @Test
    @DisplayName("Addition should return correct sum")
    void testAddition() {
        assertEquals(5, calculator.add(2, 3));
    }
    
    @Test
    void testDivisionByZero() {
        assertThrows(ArithmeticException.class, 
            () -> calculator.divide(10, 0));
    }
    
    @AfterEach
    void tearDown() {
        calculator = null;
    }
}

Mockito

Mockito is used to create mock objects for unit testing, isolating the code under test.

@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    
    @Mock
    private UserRepository userRepository;
    
    @InjectMocks
    private UserService userService;
    
    @Test
    void shouldReturnUser() {
        // Arrange
        User mockUser = new User("John");
        when(userRepository.findById(1L)).thenReturn(Optional.of(mockUser));
        
        // Act
        User result = userService.getUser(1L);
        
        // Assert
        assertEquals("John", result.getName());
        verify(userRepository, times(1)).findById(1L);
    }
}
🌍 Real-World Example

When testing a UserService, you don't want to hit a real database. Mock the UserRepository to return test data.

10. Database Connectivity

JDBC Basics

Statement Types

  • Statement: Simple SQL queries. Vulnerable to SQL injection.
  • PreparedStatement: Precompiled, parameterized queries. Safe from SQL injection.
  • CallableStatement: Calls stored procedures.
// PreparedStatement (Always use this!)
String sql = "SELECT * FROM users WHERE email = ?";
try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
    pstmt.setString(1, email);  // Parameter binding
    ResultSet rs = pstmt.executeQuery();
    while (rs.next()) {
        String name = rs.getString("name");
    }
}

ACID Properties

  • Atomicity: All operations in a transaction succeed or all fail
  • Consistency: Database moves from one valid state to another
  • Isolation: Concurrent transactions don't interfere with each other
  • Durability: Committed transactions persist even after system failure
🌍 Real-World Example: Bank Transfer

Transferring $100 from Account A to B: Debit A and Credit B must both succeed or both fail (Atomicity). The total money in the system remains the same (Consistency).

JPA/Hibernate Basics

Entity Lifecycle

  • Transient: Object created, not associated with persistence context
  • Managed: Object is tracked by persistence context
  • Detached: Was managed but persistence context is closed
  • Removed: Scheduled for deletion

Fetch Types

  • LAZY: Load related entities only when accessed (default for collections)
  • EAGER: Load related entities immediately with parent
N+1 Problem: When fetching N entities, if each entity lazily loads a collection, you get N+1 queries. Solution: Use JOIN FETCH or @EntityGraph.
