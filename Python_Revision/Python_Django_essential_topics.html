🐍 Python & Django Essential Topics

Complete Guide with Real-World Examples

1. Core Python Fundamentals

📚 Data Structures

List (ordered, mutable), Tuple (ordered, immutable), Set (no duplicates), Dictionary (key-value pairs). Choose right one for performance.
Real Example: Use Set for unique user IDs (O(1) lookup), List for ordered queue of tasks, Dict for user info storage.

🎯 List & Dictionary Comprehensions

Concise syntax for creating lists/dicts. [x*2 for x in range(5)] creates [0,2,4,6,8]. Much faster than loops.
Real Example: Extract all user IDs from user list: [user['id'] for user in users] vs manual loop - cleaner and 2x faster.

🔧 *args and **kwargs

*args for variable positional arguments (tuple), **kwargs for keyword arguments (dict). Allows flexible function signatures.
Real Example: def print_info(*names, **info): allows print_info('john', 'jane', age=30, city='NYC')

⚡ Lambda Functions

Anonymous one-line functions. lambda x: x*2 instead of def. Use with map(), filter(), sorted().
Real Example: Sort users by age: sorted(users, key=lambda u: u['age'])

🌳 Scope - LEGB Rule

Variable lookup order: Local → Enclosing → Global → Built-in. Use global/nonlocal keywords to modify outer scopes.
Real Example: Nested functions accessing outer variable: use nonlocal x to modify, else it creates new local variable.

🎭 Decorators

Functions that modify other functions. @staticmethod (no self), @classmethod (has cls), custom decorators for logging/auth.
Real Example: @login_required decorator prevents access to admin views without login.

⚙️ Generators - yield keyword

yield returns values one at a time (memory efficient). next() gets next value. Perfect for large datasets.
Real Example: Read large file line by line: generator vs loading all lines in memory.

📂 Context Managers - with statement

with open(file) as f: auto-closes file. Implement __enter__ and __exit__ methods.
Real Example: Database connection: with get_db_connection() as conn: auto-commits/closes on exit.

⚠️ Exception Handling

try-except-else-finally. else runs if no exception, finally always runs for cleanup.
Real Example: try: process_payment() except InsufficientFunds: alert_user() finally: log_transaction()

2. Object-Oriented Programming (OOP) in Python

👨‍💼 Classes & self keyword

self refers to instance, like this in Java. First parameter must be self. Methods have access to instance attributes.
Real Example: class User: def __init__(self, name): self.name = name stores name per instance.

🔄 Inheritance & MRO

MRO (Method Resolution Order) determines which parent method is called. Use super() to call parent method. C3 Linearization algorithm.
Real Example: Admin inherits from User, both have display() - MRO determines which version runs.

🦆 Polymorphism & Duck Typing

"If it walks like a duck and quacks like a duck, it's a duck" - use object by capability, not type. Python is dynamically typed.
Real Example: Function accepts anything with save() method - works with User, Profile, Settings without type checking.

🔒 Encapsulation - Name Mangling

Single underscore _variable (convention private), double underscore __variable (name mangling). Not true private, but discourages access.
Real Example: self.__password becomes self._User__password to prevent accidental access.

✨ Dunder (Magic) Methods

__init__ (constructor), __str__ (string representation), __eq__ (equality), __call__ (make object callable).
Real Example: Define __eq__ in User class to compare users by email instead of object reference.

🧬 Abstract Base Classes (ABC)

from abc import ABC, abstractmethod defines contract. Subclasses must implement abstract methods.
Real Example: Payment abstract class with process_payment() - PayPal, Stripe implement differently.

3. Advanced Python Concepts

💾 Memory Management & Reference Counting

Python counts references to objects. When count = 0, object deleted (garbage collected). Circular references handled by GC.
Real Example: a = []; b = a; del a - a's reference deleted but list still exists (b references it).

🚫 Global Interpreter Lock (GIL)

Only one thread executes Python bytecode at a time. CPU-bound tasks stay single-threaded. I/O-bound tasks benefit from threading.
Real Example: Download 100 files concurrently: threading works (I/O waits). Calculate 100M primes: multiprocessing needed (CPU-bound).

🔄 Multithreading vs Multiprocessing

Threads share memory (lightweight, GIL issue), Processes have separate memory (heavyweight, true parallelism). Choose based on workload.
Real Example: Web server (I/O) → threading. Image processing (CPU) → multiprocessing or concurrent.futures.

⚡ Async/Await

Coroutines for I/O operations. async def defines coroutine, await suspends execution. Single-threaded concurrency.
Real Example: Fetch 100 URLs: asyncio handles 100 concurrent requests with 1 thread.

📝 Type Hinting

def greet(name: str) → str: hints parameter and return types. Optional, but catches bugs early with tools like mypy.
Real Example: def get_user(user_id: int) → Optional[User]: documents what function expects/returns.

4. Django Core Architecture

🏗️ MVT Architecture

Model (database layer), View (business logic), Template (HTML rendering). Like MVC but template replaces view.
Real Example: User registration: Model stores user data, View validates input, Template shows form.

📂 Project Structure

settings.py (config), urls.py (URL routing), manage.py (commands), apps/ (features).
Real Example: Django project = store, apps = users app (auth), products app (catalog).

🔄 Request-Response Cycle

Request → Middleware → URL matching → View → Response → Middleware → Response. Middleware intercepts at each stage.
Real Example: Custom middleware logs API call duration, checks authentication before view runs.

🪝 Signals

Decoupled way to react to events. post_save (after object saved), pre_delete (before object deleted), etc.
Real Example: When user created → signal sends welcome email, creates profile, updates stats cache.

5. Django Models & ORM

💾 Defining Models & Field Types

Models map to database tables. Field types: CharField, IntegerField, ForeignKey, ManyToManyField, DateTimeField, etc.
Real Example: class Product(Model): name = CharField(...), price = DecimalField(...), category = ForeignKey(Category, ...)

🔗 Relationships - N+1 Problem

select_related() for ForeignKey (one SQL JOIN), prefetch_related() for reverse ForeignKey/ManyToMany (multiple SELECTs + Python). Avoid N+1 query problem.
Real Example: Get all orders with users: select_related('user') vs loop → 1 query vs 1000 queries.

⚡ QuerySet Optimization - values() & only()

.values('id', 'name') returns dict, fetches only those columns. .only('name') returns model instances but lazy-loads others.
Real Example: Need just user names for dropdown: User.objects.values_list('name', flat=True) vs loading all user data.

💾 Database Migrations

makemigrations detects model changes, migrate applies to database. Version control for database schema.
Real Example: Add email field to User → makemigrations → migrate → database updated automatically.

🛠️ Manager & Custom QuerySet

Extend default manager for custom queries. User.objects.published() shorter than filter(is_published=True)
Real Example: class PublishedManager: def get_queryset(): return super().get_queryset().filter(is_published=True)

6. Django Views & Templates

📋 Function-Based Views (FBV) vs Class-Based Views (CBV)

FBV is simple function, CBV is class with methods (GET, POST, etc). CBV provides built-in mixins for auth, pagination, etc.
Real Example: FBV: handle GET/POST in one function. CBV: get() and post() methods - cleaner for complex logic.

🔐 Mixins for Security

LoginRequiredMixin (auth), PermissionRequiredMixin (permissions), UserPassesTestMixin (custom logic).
Real Example: class EditUserView(LoginRequiredMixin, UpdateView): auto-redirects unauthenticated users.

🔀 URL Dispatching

path('users/<int:id>/edit', ...) extracts parameters. re_path for regex. converters for validation.
Real Example: path('posts/<slug:slug>', view) handles "my-first-post" → slug="my-first-post".

🎨 Templates & Custom Filters

Built-in filters: {{ name|lower }}, {{ items|length }}. Create custom filters for app-specific formatting.
Real Example: Custom filter {{ price|currency }} formats price with currency symbol and decimals.

🌍 Context Processors

Add variables to all templates automatically. settings.py defines processors.
Real Example: Global processor adds current site info, ads, navigation menu to every template.

7. Django REST Framework (DRF)

📤 Serializers

ModelSerializer auto-generates fields from model. Validates input, converts to/from JSON.
Real Example: class UserSerializer(ModelSerializer): class Meta: model=User, fields=['id','name','email']

🔌 API Views & ViewSets

APIView (manual handling), GenericAPIView (mixins), ViewSet (auto-generates CRUD). Routers auto-create URLs.
Real Example: class UserViewSet(ViewSet): generates list, create, retrieve, update, delete endpoints automatically.

🔑 Authentication & Authorization

Token auth (API key), JWT (tokens expire), Session (Django default), OAuth2 (third-party). Permissions control access.
Real Example: Mobile app gets JWT after login, sends in headers for protected endpoints.

📄 Pagination & Filtering

paginate_by limits results per page. Filters narrow results by field. Search filters full-text search.
Real Example: GET /api/users/?page=2&role=admin&search=john returns page 2, admin role, name contains john.

8. Testing & Deployment

🧪 Unit Testing

pytest or Django's TestCase. APITestCase for API endpoints. Mock external services.
Real Example: Test user creation: create user, check saved to DB, verify email sent (mocked).

🏭 Factory Boy

Generate test data quickly. UserFactory.create(name='test') instead of manually creating test objects.
Real Example: users = UserFactory.create_batch(100) creates 100 test users with realistic data.

🚀 Deployment

Gunicorn (WSGI server), Nginx (reverse proxy, static files), PostgreSQL (production DB).
Real Example: User requests → Nginx → Gunicorn processes → Django view → PostgreSQL, response back through Nginx.

🔐 Environment Variables

Store secrets (database URL, keys) in .env file, load with python-dotenv. Never commit secrets to git.
Real Example: DATABASE_URL=postgres://localhost/mydb, SECRET_KEY=xxxxx in .env file.
