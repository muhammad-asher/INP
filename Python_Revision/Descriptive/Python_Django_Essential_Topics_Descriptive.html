1. Core Python Fundamentals

Data Structures

Lists

Lists are ordered, mutable collections that can hold items of any type. They support indexing, slicing, and various methods for manipulation.

# List creation and operations
fruits = ["apple", "banana", "cherry"]
fruits.append("date")        # Add to end
fruits.insert(1, "mango")    # Insert at index
fruits.remove("banana")      # Remove by value
popped = fruits.pop()        # Remove and return last item

# List Comprehension - Powerful one-liner
squares = [x**2 for x in range(10)]
even_squares = [x**2 for x in range(10) if x % 2 == 0]

# Nested comprehension
matrix = [[i*j for j in range(3)] for i in range(3)]
🌍 Real-World Example: Shopping Cart

A shopping cart is like a list - you can add items, remove items, check what's at position 3, and iterate through all items.

Dictionaries

Dictionaries are key-value pairs. Keys must be immutable (strings, numbers, tuples). They provide O(1) average lookup time.

# Dictionary operations
user = {"name": "John", "age": 30, "city": "NYC"}

# Safe access with .get()
email = user.get("email", "not provided")  # Returns default if key missing

# Useful methods
keys = user.keys()       # dict_keys(['name', 'age', 'city'])
values = user.values()   # dict_values(['John', 30, 'NYC'])
items = user.items()     # dict_items([('name', 'John'), ...])

# Dictionary Comprehension
squared = {x: x**2 for x in range(5)}
# {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
Why must dictionary keys be immutable? Dictionary keys are hashed to quickly find values. If a key could change after being added, the hash would be wrong, and you'd never find your data again. It's like putting a book on shelf A, then changing the label to shelf B - the book is lost!

Tuples

Tuples are immutable, ordered collections. They're faster than lists and can be used as dictionary keys.

🌍 Real-World Example: GPS Coordinates

Coordinates like (40.7128, -74.0060) should be tuples - they represent a fixed location that shouldn't change.

Sets

Unordered collections of unique elements. Perfect for membership testing and removing duplicates.

# Set operations
a = {1, 2, 3}
b = {2, 3, 4}

print(a | b)  # Union: {1, 2, 3, 4}
print(a & b)  # Intersection: {2, 3}
print(a - b)  # Difference: {1}

# Remove duplicates from a list
numbers = [1, 2, 2, 3, 3, 3]
unique = list(set(numbers))  # [1, 2, 3]

Functions

*args and **kwargs

Allow functions to accept variable numbers of arguments.

  • *args: Collects positional arguments into a tuple
  • **kwargs: Collects keyword arguments into a dictionary
def greet(*names):
    for name in names:
        print(f"Hello, {name}!")

greet("Alice", "Bob", "Charlie")

def build_profile(**kwargs):
    return kwargs

profile = build_profile(name="John", age=30, city="NYC")
# {'name': 'John', 'age': 30, 'city': 'NYC'}
🌍 Real-World Example: Print Function

Python's built-in print() function uses *args - you can print any number of items: print("Hello", "World", 123)

Lambda Functions

Anonymous, single-expression functions. Best for short, simple operations.

# Traditional function
def square(x):
    return x ** 2

# Lambda equivalent
square = lambda x: x ** 2

# Common use: sorting with custom key
users = [{"name": "Bob", "age": 25}, {"name": "Alice", "age": 30}]
sorted_users = sorted(users, key=lambda u: u["age"])

LEGB Rule (Variable Scope)

Python looks for variables in this order:

  1. Local: Inside the current function
  2. Enclosing: In the enclosing function (for nested functions)
  3. Global: At the module level
  4. Built-in: Python's built-in names
x = "global"  # Global

def outer():
    x = "enclosing"  # Enclosing
    
    def inner():
        x = "local"  # Local
        print(x)     # Prints "local"
    
    inner()

outer()

Decorators

Decorators are functions that modify the behavior of other functions without changing their code.

def timer(func):
    """Decorator that measures execution time"""
    import time
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"{func.__name__} took {end - start:.2f}s")
        return result
    return wrapper

@timer
def slow_function():
    import time
    time.sleep(2)
    return "Done"

slow_function()  # Prints: slow_function took 2.00s
🌍 Real-World Example: Login Required Decorator

In web apps, @login_required decorator checks if user is authenticated before allowing access to a view. It wraps the view function with authentication logic.

Iterators & Generators

Iterators

An iterator is an object that implements __iter__() and __next__() methods. All iterables (list, tuple, string) can provide an iterator.

Generators

Generators are a simple way to create iterators using the yield keyword. They generate values on-demand (lazy evaluation), saving memory.

# Generator function
def countdown(n):
    while n > 0:
        yield n  # Pauses here, resumes on next iteration
        n -= 1

for num in countdown(5):
    print(num)  # 5, 4, 3, 2, 1

# Generator expression (like list comprehension but lazy)
squares = (x**2 for x in range(1000000))  # Uses minimal memory
🌍 Real-World Example: Reading Large Files

Instead of loading a 10GB log file into memory, a generator can yield one line at a time, processing the file piece by piece.

Why use generators? If you need to process 1 million records but only need one at a time, a generator produces them on-demand. A list would store all 1 million in memory.

Context Managers (with statement)

Context managers ensure proper resource management by automatically handling setup and cleanup.

# File handling with context manager
with open("data.txt", "r") as file:
    content = file.read()
# File is automatically closed, even if exception occurs

# Custom context manager
class DatabaseConnection:
    def __enter__(self):
        print("Opening connection")
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        print("Closing connection")
        return False  # Don't suppress exceptions

with DatabaseConnection() as db:
    print("Using database")
🌍 Real-World Example: Database Transactions

A context manager can start a transaction on __enter__ and commit/rollback on __exit__ based on whether an exception occurred.

Exception Handling

try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"Error: {e}")
except (TypeError, ValueError) as e:
    print(f"Type or Value Error: {e}")
else:
    print("No exception occurred")  # Runs only if no exception
finally:
    print("Cleanup")  # Always runs

# Raising exceptions
def validate_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

2. Object-Oriented Programming (OOP) in Python

Classes & Objects

class Dog:
    species = "Canis familiaris"  # Class attribute
    
    def __init__(self, name, age):
        self.name = name  # Instance attribute
        self.age = age
    
    def bark(self):
        return f"{self.name} says woof!"
    
    def __str__(self):
        return f"{self.name} is {self.age} years old"

buddy = Dog("Buddy", 5)
print(buddy.bark())  # Buddy says woof!

Inheritance & MRO

Python supports multiple inheritance. Method Resolution Order (MRO) determines which method is called when multiple parents have the same method.

class Animal:
    def speak(self):
        return "Some sound"

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

# Multiple inheritance
class DogCat(Dog, Cat):
    pass

hybrid = DogCat()
print(hybrid.speak())  # Woof! (Dog comes first in MRO)
print(DogCat.__mro__)  # Shows the resolution order

Duck Typing

"If it walks like a duck and quacks like a duck, it's a duck." Python cares about what an object can do, not what it is.

class Duck:
    def swim(self):
        print("Duck swimming")

class Person:
    def swim(self):
        print("Person swimming")

def make_swim(thing):
    thing.swim()  # Works with any object that has swim()

make_swim(Duck())    # Duck swimming
make_swim(Person())  # Person swimming
🌍 Real-World Example: File-like Objects

Any object with read() and write() methods can be used as a "file" - actual files, StringIO, network sockets, etc.

Dunder (Magic) Methods

Special methods that Python calls automatically in certain situations.

Method Purpose Called When
__init__ Constructor Object creation
__str__ User-friendly string print(), str()
__repr__ Developer string repr(), debugging
__eq__ Equality comparison == operator
__len__ Length len()
__call__ Make object callable object() 
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)
    
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
    
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)
v3 = v1 + v2  # Calls __add__
print(v3)     # Vector(4, 6) - Calls __repr__

Abstract Base Classes

Define interfaces that subclasses must implement.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass
    
    @abstractmethod
    def perimeter(self):
        pass

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    
    def area(self):
        return self.width * self.height
    
    def perimeter(self):
        return 2 * (self.width + self.height)

# shape = Shape()  # TypeError: Can't instantiate abstract class
rect = Rectangle(5, 3)
print(rect.area())  # 15

3. Advanced Python Concepts

Global Interpreter Lock (GIL)

The GIL is a mutex that protects access to Python objects, preventing multiple threads from executing Python bytecode simultaneously.

Impact: In CPython, only one thread can execute Python code at a time, even on multi-core systems. This makes CPU-bound tasks not benefit from threading.

When to use Threading vs Multiprocessing

Task Type Use Reason
I/O-bound (network, disk) Threading GIL is released during I/O waits
CPU-bound (calculations) Multiprocessing Bypasses GIL with separate processes
🌍 Real-World Example

Threading: Web scraper fetching 100 URLs - while waiting for one response, other threads can start their requests.

Multiprocessing: Image processing on 100 photos - each CPU core processes different images in parallel.

Async/Await (Asyncio)

Asynchronous programming allows handling many I/O operations concurrently without threads, using an event loop.

import asyncio

async def fetch_data(url):
    print(f"Fetching {url}")
    await asyncio.sleep(2)  # Simulates I/O wait
    return f"Data from {url}"

async def main():
    # Run multiple coroutines concurrently
    tasks = [
        fetch_data("url1"),
        fetch_data("url2"),
        fetch_data("url3")
    ]
    results = await asyncio.gather(*tasks)
    print(results)

asyncio.run(main())  # All 3 complete in ~2s, not 6s
🌍 Real-World Example: Chat Server

A chat server handling 10,000 connections. Instead of 10,000 threads, asyncio uses one thread that switches between connections as they have data to send/receive.

Type Hinting

Type hints don't enforce types at runtime but help with documentation, IDE support, and static analysis tools like mypy.

from typing import List, Dict, Optional, Union

def process_items(items: List[int]) -> Dict[str, int]:

def find_user(user_id: int) -> Optional[str]:
    """Returns username or None if not found"""
    users = {1: "Alice", 2: "Bob"}
    return users.get(user_id)

def parse_input(value: Union[str, int]) -> int:
    return int(value)

🌐 What is Django?

Django is a high-level Python web framework that encourages rapid development and clean, pragmatic design. It follows the "batteries included" philosophy.

MVT Architecture

Django uses Model-View-Template architecture, similar to MVC:

MVT (Django) MVC (Traditional) Responsibility

Template View Presentation/HTML rendering
🌍 Real-World Example: Blog Application

Model: BlogPost class with title, content, author fields
View: Function that fetches posts and passes to template
Template: HTML that displays the list of posts

Request-Response Cycle

Understanding the flow of a request through Django:

  1. Middleware (Request): Process incoming request
  2. URL Resolver: Match URL to view
  3. View: Process request, interact with models
  4. Template: Render HTML (if needed)
  5. Middleware (Response): Process outgoing response
  6. Response: Sent back to client
# urls.py
from django.urls import path
from . import views

urlpatterns = [
    path('posts/', views.post_list, name='post_list'),
    path('posts/<int:pk>/', views.post_detail, name='post_detail'),
]

# views.py
from django.shortcuts import render, get_object_or_404
from .models import Post

def post_list(request):
    posts = Post.objects.all()
    return render(request, 'blog/post_list.html', {'posts': posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk)
    return render(request, 'blog/post_detail.html', {'post': post})

Middleware

Middleware is a framework of hooks that processes requests and responses globally before they reach views or after they leave.

# Custom middleware
class RequestTimingMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response
    
    def __call__(self, request):
        import time
        start = time.time()
        
        response = self.get_response(request)  # Call the view
        
        duration = time.time() - start
        response['X-Request-Duration'] = str(duration)
        return response

# settings.py
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'myapp.middleware.RequestTimingMiddleware',  # Your custom middleware
    'django.contrib.sessions.middleware.SessionMiddleware',
    # ...
]

Signals

Signals allow decoupled applications to get notified when certain actions occur (like model saves).

from django.db.models.signals import post_save, pre_delete
from django.dispatch import receiver
from .models import User, Profile

@receiver(post_save, sender=User)
def create_user_profile(sender, instance, created, **kwargs):
    """Automatically create a Profile when a User is created"""
    if created:
        Profile.objects.create(user=instance)

@receiver(pre_delete, sender=User)
def cleanup_user_data(sender, instance, **kwargs):
    """Clean up related data before user deletion"""
    instance.cleanup_files()
🌍 Real-World Example: User Registration

When a new user registers, a signal can automatically create their profile, send a welcome email, and initialize default settings - all without cluttering the registration view.

QuerySets & The N+1 Problem

QuerySets are lazy - they don't hit the database until evaluated. This can lead to the N+1 problem.

# N+1 Problem Example
books = Book.objects.all()  # 1 query
for book in books:
    print(book.author.name)  # N additional queries!

# Solution: select_related (for ForeignKey/OneToOne)
books = Book.objects.select_related('author').all()  # 1 query with JOIN

# prefetch_related (for ManyToMany/reverse ForeignKey)
authors = Author.objects.prefetch_related('books').all()  # 2 queries total
Rule of Thumb: Use select_related() for "forward" relationships (ForeignKey) - it does a SQL JOIN. Use prefetch_related() for "reverse" or Many-to-Many - it does separate queries then joins in Python.

QuerySet Optimization Methods

# Get only specific fields
Book.objects.values('title', 'price')  # Returns dictionaries
Book.objects.values_list('title', flat=True)  # Returns flat list ['Book1', 'Book2']

# Load only certain fields (deferred loading)
Book.objects.only('title', 'price')  # Load only these
Book.objects.defer('description')  # Load all except these

# Efficient counting
Book.objects.count()  # Uses COUNT(*), not len(books)

# Existence checking
Book.objects.filter(price__gt=100).exists()  # Fast boolean check

# Bulk operations
Book.objects.filter(author=author).update(is_available=False)  # Single query
Book.objects.bulk_create([Book(...), Book(...), Book(...)])  # Insert multiple

7. Django REST Framework (DRF)

Serializers

Serializers convert complex data like QuerySets and model instances to native Python datatypes that can be rendered into JSON.

from rest_framework import serializers
from .models import Book, Author

class AuthorSerializer(serializers.ModelSerializer):
    class Meta:
        model = Author
        fields = ['id', 'name', 'email']

class BookSerializer(serializers.ModelSerializer):
    author = AuthorSerializer(read_only=True)
    author_id = serializers.PrimaryKeyRelatedField(
        queryset=Author.objects.all(),
        source='author',
        write_only=True
    )
    
    class Meta:
        model = Book
        fields = ['id', 'title', 'author', 'author_id', 'price', 'is_available']
    
    def validate_price(self, value):
        if value < 0:
            raise serializers.ValidationError("Price cannot be negative")
        return value

ViewSets & Routers

# views.py
from rest_framework import viewsets
from rest_framework.decorators import action
from rest_framework.response import Response

class BookViewSet(viewsets.ModelViewSet):
    queryset = Book.objects.all()
    serializer_class = BookSerializer
    
    @action(detail=False, methods=['get'])
    def available(self, request):
        """Custom endpoint: /api/books/available/"""
        books = self.queryset.filter(is_available=True)
        serializer = self.get_serializer(books, many=True)
        return Response(serializer.data)

# urls.py
from rest_framework.routers import DefaultRouter

router = DefaultRouter()
router.register(r'books', BookViewSet)

urlpatterns = router.urls  # Automatically creates CRUD URLs
